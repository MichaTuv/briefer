# MentorAI v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild MentorAI as a mobile-first, modern-Bauhaus Hebrew voice mentor with a tool-using live voice agent, three-panel layout (right conversations / left notes / top progress), compact expandable chat feed, pause/resume with full context, and a cross-conversation learning profile.

**Architecture:** Express server proxies Gemini (PDF analysis, 5-candidate Socratic chat, Live API voice over WebSocket). Client is React 19 + Tailwind v4, state in localStorage via a `useProjects` store hook. Voice tool calls flow model → server → WS → client store → WS → model. One shared mentor-prompt module feeds all three AI paths.

**Tech Stack:** React 19, Vite 6, Tailwind v4, Express, ws, @google/genai (Live API + generateContent), motion, lucide-react. Hebrew RTL only.

## Global Constraints

- Hebrew UI, `dir="rtl"` everywhere; voice/transcription he-IL.
- Bauhaus palette tokens: red #E03C31, blue #00509E, yellow #F2B705, black #1A1A1A, beige #F3F1E7.
- Mobile-first: root `h-[100dvh]`, safe-area insets; drawers overlay < 1024px, dock ≥ 1024px (`lg:`).
- No git commits (not a repo). Verify each task with `npm run lint` (tsc --noEmit).
- Keep the 5-candidate scoring engine in `/api/chat`.
- Socratic hard rules (all prompts): no solutions, no option lists, one open question per turn, no proactive interpretation, linear roadmap with branch-reminders, explicit user consent before any note/roadmap mutation.
